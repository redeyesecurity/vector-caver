# Golden-event test fixtures

Tracked: caver-collector#75, caver-collector#897

Convention per vendor scenario:
```
caver/tests/golden/<vendor>_<scenario>/
  in.json    # raw input event, with the `_vendor` routing tag set
  out.json   # expected OCSF output
```

Directories are vendor-keyed, not class_uid-keyed: several vendors share one
OCSF class (zeek conn and suricata are both 4001 Network Activity) and one
vendor spans several classes.

The test harness in `vrl-caver-stdlib` (`tests/golden.rs`) loads these
fixtures and runs them through `ocsf::normalize()` as snapshot tests.

For the vendors mirrored from the Python collector transforms (#897 —
suricata, zeek, palo_alto, fortinet), `out.json` is **generated by the Python
transform itself** (`src/caver_collector/transforms/<vendor>_normalize.py` in
caver-collector), so the snapshot asserts the Rust port emits the identical
OCSF-flat contract. When the Python contract changes, regenerate `out.json`
with the Python `normalize()` on `in.json` (minus the `_vendor` key).
